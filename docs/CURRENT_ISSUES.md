## 2. 问题清单

### ISSUE-001：GEANT 类别拆分与论文描述不一致

- 状态：待确认
- 优先级：P0
- 涉及文件：`prepare_geant/prepare_geant_hattrick.py`
- 当前实现：每个 OD、每个快照独立采样 High 45%-50%、Medium 40%-45%，Low 为剩余的 5%-15%。
- 论文描述：GEANT 类别比例来自 PrivateWAN；论文报告的 PrivateWAN 比例范围约为 High 23%-42%、Medium 21%-38%、Low 25%-46%。当前比例更接近论文对 USCarrier/KDL 合成流量的设置。
- 影响：类别负载结构、预测误差和低优先级压力均发生变化，当前结果不能作为论文数值的严格复现。
- 处理建议：向作者确认拆分规则；在无法获得原始比例时，至少比较多种拆分策略和三个随机种子，并保存拆分元数据。

### ISSUE-002：候选路径数与论文不一致

- 状态：已知差异
- 优先级：P0
- 涉及文件：运行脚本、路径缓存、Gurobi 结果和模型权重
- 当前实现：GEANT 使用 K=4。
- 论文设置：GEANT 使用 K=8。
- 影响：可行路由空间和优化参考值不同，不能直接对齐论文图表。
- 验收标准：以 K=8 重新生成路径、oracle、BEST_MC、SWAN，并完成同一数据切分下的训练和测试。

### ISSUE-003：测试默认加载最后一轮模型，而非验证集最优模型

- 状态：待修复
- 优先级：P0
- 涉及文件：`run_hattrick.py`
- 当前实现：训练每轮覆盖 `hattrick_<topology>_<K>sp.pkl`，测试固定加载该文件；`hp_search` 中的较优模型没有被测试入口使用。
- 影响：报告结果可能来自最后一轮而非最优验证轮次。
- 验收标准：明确保存 `best.pt`、`last.pt`、`checkpoint.pt`，测试入口通过参数选择并在结果中记录权重来源。

### ISSUE-004：最优模型选择条件不是严格词典序

- 状态：待修复
- 优先级：P0
- 涉及文件：`run_hattrick.py`
- 当前实现：使用多组手工容差条件决定是否覆盖最佳模型。
- 影响：可能在高优先级指标退化时仍保存新模型，也难以解释模型选择逻辑。
- 验收标准：实现显式的优先级/词典序比较器，并为边界条件添加测试。

### ISSUE-005：GPU 推理计时不准确，且硬件不统一

- 状态：待修复
- 优先级：P0
- 涉及文件：`run_hattrick.py`、`summarize_geant_results.py`
- 当前实现：使用 `time.time()` 包围 GPU 前向传播，没有 CUDA 同步；Hattrick 和 Gurobi 基线来自不同硬件。
- 影响：GPU 异步执行可能低估推理耗时；当前图不能用于严格宣称加速比。
- 验收标准：使用 CUDA Event 或同步计时，报告 warm-up、冷启动和稳态时间；受控加速比必须在相同硬件/环境下测量。

### ISSUE-006：GEANT 运行配置缺少多随机种子结果

- 状态：待补充
- 优先级：P1
- 涉及文件：运行脚本、结果汇总脚本
- 当前实现：模型训练主要使用固定 seed=490，类别拆分使用 seed=42。
- 影响：无法判断当前尾部提升是否稳定，也无法报告置信区间。
- 验收标准：至少运行三个训练种子；输出均值、标准差和 95% 置信区间。

### ISSUE-007：训练存在明显工程开销

- 状态：待优化
- 优先级：P1
- 涉及文件：`run_hattrick.py`、`utils/training_utils.py`、`utils/build_dataset_within_cluster.py`、`utils/snapshot_utils.py`
- 已确认现象：始终开启 autograd anomaly detection；每个 batch 多次调用 `torch.cuda.empty_cache()`；验证 batch size 为 1；每个 epoch 重新创建并读取完整 Dataset；loss 内逐样本 `.item()`；TM 在加载时重复 K 份。
- 影响：当前约 20 小时训练中，验证和重复数据构建占据较大比例，且扩展到大拓扑时内存和 I/O 压力会明显增加。
- 验收标准：在模型指标误差不超过约定容差的前提下，记录优化前后每 epoch 时间、验证时间、峰值显存和总训练时间。

### ISSUE-008：梯度投影的异常处理和数值稳定性不足

- 状态：待修复
- 优先级：P1
- 涉及文件：`utils/robust_proj_utils.py`
- 当前实现：使用 broad `except`、`exit(1)`、精确零判断以及对完整梯度向量的多次复制；部分失败路径只对最高优先级梯度投影。
- 影响：数值异常时可能偏离论文中的优先级投影语义，且增加显存和反向传播开销。
- 验收标准：使用稳定的 QR/SVD 或伪逆实现，测试投影后低优先级梯度与受保护子空间近似正交。

### ISSUE-009：多 cluster 验证汇总存在变量使用错误

- 状态：待修复
- 优先级：P1
- 涉及文件：`utils/training_utils.py`
- 当前实现：`validate()` 最终的 all-traffic 汇总使用最后一个 cluster 的局部变量，而不是已经收集的 `all_traffic_list`。
- 影响：单 cluster GEANT 不受影响，多 cluster 或动态拓扑训练时汇总错误。
- 验收标准：修正聚合变量并添加双 cluster 单元测试。

### ISSUE-010：输出口径和实验元数据尚未完全统一

- 状态：部分缓解
- 优先级：P1
- 涉及文件：`run_hattrick.py`、`summarize_geant_results.py`
- 当前实现：不同拓扑的测试文件含义不完全相同；跨方案 MLU 在部分接纳流量下不可直接比较；原始输出没有统一记录 commit、配置、硬件和权重来源。
- 影响：结果容易被误读，后续多数据集汇总困难。
- 验收标准：使用统一 CSV/JSON schema，记录 Git commit、数据拆分 ID、seed、K、预测器、模型权重、硬件和指标定义。

### ISSUE-011：缺少自动化测试

- 状态：待建设
- 优先级：P1
- 涉及文件：新建 `tests/`
- 建议覆盖：每个 OD 的 K 条路径分流和为 1；模拟器输出不超过容量；优先级残余容量正确；梯度投影满足正交约束；manifest/TM/pairs 对齐；统计百分位定义正确。
